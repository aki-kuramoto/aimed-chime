# aimed-chime

> **Note:** The second half of this document is available in Japanese (日本語).

An MCP server (stdio) that lets an AI agent tell you what is going on with a chime or spoken text.
It is mainly intended for uses such as letting you know when the agent has finished its work or needs your decision.
The sound goes to an audio output device chosen by name, not to the system default output.

- Three tools: `chime` (a three-tone chime, repeated the given number of times), `speak` (text-to-speech) and `list_devices`
- The device is passed as the `device` argument on every call, as part of the device name or UID. If it is omitted, the device marked `default` in the config file is used
- `list_devices` lays the `remarks` you wrote in the config file and the volumes over the actual devices, so the agent can use them to choose a device. For example, writing in the remarks which kind of work each device is for lets you hear different devices for different work
- Input-only devices (microphones) are never candidates
- Device indexes change when devices are plugged in or out, so the device is looked up by name on every call. If it cannot be found, the call fails; it never falls back to the default output
- Calls from several sessions are played one at a time (a lock file in `~/.app-data/aimed-chime/`), so sounds never overlap

## Platforms

| Platform | Status | Requirements |
|---|---|---|
| macOS | Supported | Go, a C toolchain for cgo (Xcode Command Line Tools), [ffmpeg](https://ffmpeg.org/) |
| Windows 10 / 11 | Supported | Go (no cgo and no ffmpeg needed) |

## Installation

1. Check the requirements for the platform in the table above, for example with `go version` (and `ffmpeg -version` and `xcode-select -p` on macOS).
2. Install:
   ```bash
   go install github.com/aki-kuramoto/aimed-chime/cmd/aimed-chime@latest
   ```
3. Find the absolute path of the installed binary: `$(go env GOBIN)/aimed-chime` if `GOBIN` is set, otherwise `$(go env GOPATH)/bin/aimed-chime` (`aimed-chime.exe` on Windows).
4. Register it with the MCP client as a stdio server whose command is `<absolute path> serve`. For Claude Code:
   ```bash
   claude mcp add --scope user aimed-chime -- "$(go env GOPATH)/bin/aimed-chime" serve
   ```
   On Windows (PowerShell):
   ```powershell
   claude mcp add --scope user aimed-chime -- "$(go env GOPATH)\bin\aimed-chime.exe" serve
   ```
5. Check that it can see the audio devices. This does not make any sound (`chime` and `speak` do):
   ```bash
   "$(go env GOPATH)/bin/aimed-chime" devices
   ```
   On Windows (PowerShell):
   ```powershell
   & "$(go env GOPATH)\bin\aimed-chime.exe" devices
   ```
6. Optionally, write the [config file](#config-file) to give each device remarks and volumes.
7. MCP clients load the server when a session starts, so the tools are available from the next session.

## Config file

`~/.app-data/aimed-chime/config.setay` (`%USERPROFILE%\.app-data\aimed-chime\config.setay` on Windows), in the [setay](https://github.com/aki-kuramoto/setay-go) format.
See [config.example.setay](config.example.setay).

- It is optional. Without it there are no remarks, and `device` is required on every call
- It is read again on every call, so edits take effect without restarting the server
- Unknown keys are errors, so typos are not silently ignored

| Key | Default | Meaning |
|---|---|---|
| `devices` | none | List of `{ match; remarks; default; chime-volume; speech-volume }`, one per device |
| `chime-volume` | 6 | Chime volume (a multiplier, like ffmpeg's volume filter) |
| `speech-volume` | 1.4 | Speech volume (a multiplier, like `chime-volume`) |
| `voice` | system default | Text-to-speech voice. macOS: a name from `say -v '?'`. Windows: a SAPI voice name such as `Microsoft Haruka Desktop`; an unknown name fails with the list of installed voices |
| `ffmpeg` | auto | Path to ffmpeg (macOS only; Windows does not use ffmpeg). Otherwise PATH and the usual install locations are searched |

## Trying it by hand

```bash
aimed-chime devices
aimed-chime chime --device "Desk Speaker" --count 2
aimed-chime speak --device "Desk Speaker" The work is done. Please take a look.
aimed-chime speak --device "Desk Speaker" --voice "name of an installed voice" The work is done.
```

## How it plays

- Chime: three sine tones (880, 660 and 990 Hz), one second apart when repeated
- Speech: rendered to a file with the system's text-to-speech first and then played, because the text-to-speech command has no gain option
- macOS: both are played through ffmpeg's audiotoolbox output, with device names and channel counts read from CoreAudio.
  1.5 seconds of silence is appended to speech, because the end of the speech was cut off without it in the environments tested
- Windows: the chime is generated by aimed-chime itself and both are played through WASAPI (shared mode, so other sounds keep playing).
  Speech is rendered with SAPI (`System.Speech`) through Windows PowerShell 5.1, so only SAPI voices can be used; some voices listed in the Windows settings are not SAPI voices.
  Playback waits until the device has played the last sample, so no silence is appended

## Development

These scripts are for working on aimed-chime itself; users install it with `go install` as above.

```bash
go run ./tools/local-install            # go vet, go test, then build and install where `go install` would put it
go run ./tools/local-install -q         # skip go vet and go test
go run ./tools/local-install -dir DIR   # install into DIR instead
```

`local-install` builds the binary next to the destination under a temporary name and moves it into place,
so MCP servers running from the old binary keep working (on Windows the running binary is renamed aside first).

# aimed-chime (日本語)

AI エージェントが、チャイムや音声の読み上げでユーザーに状況を知らせられるようにする MCP サーバー (stdio) です。
エージェントの作業が終わった時や、ユーザーの判断が必要になった時などに知らせる用途を主に想定しています。
音はシステムのデフォルト出力ではなく、名前で選んだオーディオ出力デバイスから鳴らします。

- ツールは 3 つです: `chime` (3 音のチャイムを指定の回数)、`speak` (文の読み上げ)、`list_devices`
- デバイスは、ツールの引数 `device` に名前か UID の一部を渡して、毎回指定します。省略した時は、設定ファイルで `default` を付けたデバイスを使います
- `list_devices` は、設定ファイルに書いたデバイスごとの `remarks` と音量を、実際のデバイスに重ねて返します。エージェントはそれを見てデバイスを選べます。たとえば remarks に、どの種類の作業の時に鳴らしてほしいかを書いておくと、作業によって鳴らすデバイスを使い分けられて便利です
- 入力専用のデバイス (マイク) は候補にしません
- デバイスの番号は抜き差しのたびに変わるので、鳴らすたびに名前で探し直します。見つからなければエラーにし、デフォルト出力には逃げません
- 複数のセッションから同時に呼ばれても音が重ならないよう、`~/.app-data/aimed-chime/` のロックファイルで 1 つずつ順に鳴らします

## 対応環境

| 環境 | 状況 | 必要なもの |
|---|---|---|
| macOS | 対応済み | Go、cgo 用の C ツールチェーン (Xcode Command Line Tools)、[ffmpeg](https://ffmpeg.org/) |
| Windows 10 / 11 | 対応済み | Go (cgo と ffmpeg は不要) |

## インストール

1. 上の表で、その環境に必要なものが揃っているか確かめます。たとえば `go version` です (macOS では `ffmpeg -version` と `xcode-select -p` も)。
2. インストールします:
   ```bash
   go install github.com/aki-kuramoto/aimed-chime/cmd/aimed-chime@latest
   ```
3. インストールされたバイナリの絶対パスを確かめます。`GOBIN` が設定されていれば `$(go env GOBIN)/aimed-chime`、無ければ `$(go env GOPATH)/bin/aimed-chime` です (Windows では `aimed-chime.exe`)。
4. MCP クライアントに、コマンドが `<絶対パス> serve` の stdio サーバーとして登録します。Claude Code なら次のとおりです:
   ```bash
   claude mcp add --scope user aimed-chime -- "$(go env GOPATH)/bin/aimed-chime" serve
   ```
   Windows (PowerShell) では次のとおりです:
   ```powershell
   claude mcp add --scope user aimed-chime -- "$(go env GOPATH)\bin\aimed-chime.exe" serve
   ```
5. オーディオデバイスが見えているか確かめます。これは音を出しません (音を出すのは `chime` と `speak` です):
   ```bash
   "$(go env GOPATH)/bin/aimed-chime" devices
   ```
   Windows (PowerShell) では次のとおりです:
   ```powershell
   & "$(go env GOPATH)\bin\aimed-chime.exe" devices
   ```
6. 必要なら[設定ファイル](#設定ファイル)を書いて、デバイスごとの remarks と音量を設定します。
7. MCP クライアントはセッションの開始時にサーバーを読み込むので、ツールは次のセッションから使えます。

## 設定ファイル

`~/.app-data/aimed-chime/config.setay` (Windows では `%USERPROFILE%\.app-data\aimed-chime\config.setay`) に [setay](https://github.com/aki-kuramoto/setay-go) 形式で書きます。
書き方は [config.example.setay](config.example.setay) を見てください。

- 無くても動きます。その時は remarks が無く、毎回 `device` の指定が要ります
- 鳴らすたびに読み直すので、書き換えてもサーバーの再起動は要りません
- 知らないキーはエラーにします (書き間違いを黙って無視しないため)

| キー | 既定 | 内容 |
|---|---|---|
| `devices` | なし | デバイスごとの `{ match; remarks; default; chime-volume; speech-volume }` のリスト |
| `chime-volume` | 6 | チャイムの音量 (ffmpeg の volume フィルターと同じ倍率) |
| `speech-volume` | 1.4 | 読み上げの音量 (`chime-volume` と同じ倍率) |
| `voice` | システムの声 | 読み上げの声。macOS では `say -v '?'` に出る名前、Windows では `Microsoft Haruka Desktop` のような SAPI の声の名前です。無い名前を指定すると、インストール済みの声の一覧つきでエラーにします |
| `ffmpeg` | 自動 | ffmpeg のパス (macOS のみ。Windows では ffmpeg を使いません)。指定が無ければ PATH とよくある場所から探します |

## 手で試す

```bash
aimed-chime devices
aimed-chime chime --device "Desk Speaker" --count 2
aimed-chime speak --device "Desk Speaker" 作業が終わりました。続きを確認して下さい。
aimed-chime speak --device "Desk Speaker" --voice "インストール済みの声の名前" 作業が終わりました。
```

## 鳴らし方

- チャイム: 3 つのサイン波 (880、660、990 Hz) です。繰り返す時は 1 秒あけます
- 読み上げ: システムの読み上げ機能で一度ファイルに書き出してから鳴らします。読み上げのコマンドには音量の指定が無いためです
- macOS: どちらも ffmpeg の audiotoolbox 出力で鳴らします。デバイス名とチャンネル数は CoreAudio から読みます。
  読み上げの末尾に 1.5 秒の無音を足しています。確認した環境では、足さないと最後が切れたためです
- Windows: チャイムは aimed-chime 自身が作り、どちらも WASAPI で鳴らします (共有モードなので、他の音は止めません)。
  読み上げは Windows PowerShell 5.1 経由の SAPI (`System.Speech`) で書き出すので、使える声は SAPI の声だけです。Windows の設定に出る声の中には SAPI の声でないものもあります。
  デバイスが最後の音まで鳴らし終えるのを待ってから戻るので、無音は足していません

## 開発

次のスクリプトは aimed-chime 自体を開発するためのものです。利用者は、上のとおり `go install` で入れます。

```bash
go run ./tools/local-install            # go vet、go test のあと、ビルドして `go install` と同じ場所に入れる
go run ./tools/local-install -q         # go vet と go test を省く
go run ./tools/local-install -dir DIR   # DIR に入れる
```

`local-install` は、入れる先と同じ場所に一時的な名前でビルドしてから差し替えるので、古いバイナリで動いている MCP サーバーはそのまま動き続けます (Windows では、動いているバイナリの名前を先に変えて退避します)。
